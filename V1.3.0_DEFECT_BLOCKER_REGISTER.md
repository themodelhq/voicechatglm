# v1.3.0 defects, limits, and deployment blockers

## Classification rule

A source implementation, static validation, pg-mem migration exercise, mocked controlled HTTP upstream, or local OCR fixture is not evidence of a deployed external service. The status below is intentionally no higher than the available evidence.

| ID | Status | Limitation / blocker | Required evidence before closure |
| --- | --- | --- | --- |
| API-DEPLOY-01 | Open | No Render or Netlify deployment was authorized or performed. `render.yaml` is configuration intent, not platform acceptance. | Operator-approved deployment and browser/API smoke checks without exposing secrets. |
| API-MIGRATION-02 | Open | Migration `009_api_key_management.sql` was exercised only with disposable pg-mem. No managed PostgreSQL migration, backup, lock contention or downgrade operation was run. | Backup/restore point, controlled nonproduction PostgreSQL migration/status check and migration-log review. |
| API-REDIS-03 | Open | Shared limiter code/config is controlled-tested locally; no Redis-compatible service connection, multi-instance lease/release, failover or capacity exercise occurred. | Nonproduction Redis multi-instance protection/revocation/capacity verification. |
| API-MODEL-04 | Open | The public route uses the retained fixed-model proxy path, but no protected model endpoint was contacted. Response schema, latency and revision availability remain unverified live. | Approved controlled key request against the real protected service and safe response/log review. |
| API-KEY-05 | Open | No live browser/session user flow, external secret-manager integration, key recovery exercise, operator audit-log review or actual cross-instance revoke was run. | Controlled sign-in/create/store/use/revoke test with sanitized evidence. |
| API-CORS-06 | Open | Source/actual local HTTP tests show no v1 CORS headers. CDN/proxy behavior is unverified. | Deployed-origin header inspection from an untrusted browser origin. |
| OCR-RETENTION-07 | Retained open boundary | v1.2.9 genuine local engine fixtures remain evidence only for the checked-in English typed-text files. No staging/production OCR, scanner, private storage, worker or real user document was used. | Separate approved environment acceptance under scanner/private-storage controls. |
| SECURITY-08 | Ongoing | Secret safety depends on deployment log/observability and operator practices. The source does not log key values, but deployed middleware/platform telemetry was not inspected. | Safe logging/monitoring review and rotation procedure drill. |

## Non-goals retained

- No subscription, payment, credits, commercial quota, premium endpoint, or model-access tier was added.
- No model retraining, replacement, upload, self-hosting, asset contact or internal credential exposure occurred.
- No public document/file, storage, artifact, memory, share, administration, model-selection, streaming, arbitrary upstream, or arbitrary tool endpoint was added to `/v1`.
- No claim is made that a staging environment exists. If an operator configures one through a dashboard, it must be assessed separately.

## Safe rollback posture

Migration 009 is additive. A code rollback must not drop `api_keys` or audit rows in place. First disable public API traffic, revoke affected keys where appropriate, allow active bounded work to drain/fail safely, retain data and backups, then deploy the matched prior application artifact only after its session/auth/model configuration is checked. See `ROLLBACK.md`; no rollback was executed for this release.
