# v1.2.7 OCR activation and operational boundary

## What is implemented

This release includes a genuine server-side OCR engine: exact production dependencies `tesseract.js@5.1.1` and `@tesseract.js-data/eng@1.0.0`. The English language data is resolved from the installed package; there is no browser OCR request, system `tesseract` binary, remote language download, or provider credential in frontend code.

`KNOWLEDGE_OCR_PROVIDER=tesseract_js` processes one scanner-approved private PNG, JPEG or WebP object at a time. It validates the detected format, byte and pixel limits, timeout/cancellation, bounded text output and page ordering. The worker stores only owner-scoped source/page/chunk records. `GET /api/knowledge/sources/:sourceId/pages` returns extracted text only to that source owner.

The built-in smoke fixture contains only `VOICECHAT OCR 2026`. Readiness performs a real recognition of that fixture before reporting local OCR as reachable. It proves the package, English data and runtime worker can run; it does **not** prove storage, scanner, PostgreSQL, Redis, Render or user-flow acceptance.

## Deliberate limitations

- Local Tesseract support is **PNG/JPEG/WebP only** and English only.
- Text-based PDFs keep the existing native extraction path. A scanned PDF with no native text is rejected with `OCR_PDF_RENDERER_UNAVAILABLE`; this release does not falsely claim PDF raster OCR.
- Remote OCR remains an explicit optional `KNOWLEDGE_OCR_PROVIDER=remote` adapter, but is not the local engine and has no readiness claim unless an operator verifies its own private service.
- OCR is not a malware scanner and never bypasses scanner success.

## Security and recovery controls

1. The knowledge route rejects any source whose upload state is not `inspection_completed`, `analysis_completed`, or `partially_analyzed`.
2. The worker repeats that check before native or OCR processing. Scanner outage, timeout, ambiguous state, deletion, or a missing private object fails closed.
3. Object access is through the existing private object store and owner-scoped repository calls. OCR receives bounded bytes, not a filename/path or public URL.
4. A second active non-delete job for a source returns the existing job instead of creating duplicate OCR work. Expired leases are returned to the queue or made terminal after their bounded retry count.
5. Empty recognition is retained as a truthful `partial` source with `completed_no_text` metadata and a page record; it is never indexed as page-marker-only text.
6. Jobs, pages, chunks, embedding records and source routes are owner-scoped. No public OCR-result URL is created.

## Render activation procedure

The checked-in `render.yaml` is an **activation profile**, not evidence that a live deployment passed. It selects `tesseract_js` for both API and `voicechatglm-knowledge-worker`; `npm ci --omit=dev` installs the exact pinned packages.

Before deploying or setting `KNOWLEDGE_OCR_ENABLED=true` manually:

1. Keep the model identifier/revision unchanged: `themodelhq/voicechatglm-qwen3-8b` at `9f25d05035bfda0de9b36dfc5911ddcdb378f3c8`.
2. Provision real private object storage, ClamAV/equivalent scanning, PostgreSQL with current migrations, shared Redis-compatible limiter, first-party auth, and the protected model service. Do not expose any of their credentials through `VITE_*` variables.
3. Set these server/worker variables, using the limits from `.env.v127.example`:
   - `KNOWLEDGE_BASE_ENABLED=true`
   - `KNOWLEDGE_WORKER_ENABLED=true` (worker only)
   - `KNOWLEDGE_OCR_ENABLED=true`
   - `KNOWLEDGE_OCR_PROVIDER=tesseract_js`
   - `KNOWLEDGE_OCR_LANGUAGE=eng`
4. Deploy API and worker from the same release. In production the API refuses to listen if file-analysis/OCR dependency verification or the local OCR smoke recognition fails; the private worker also exits rather than claiming work when its enabled local OCR smoke probe fails.
5. Check the authenticated deployment's readiness response. It must show `ocr.enabled=true`, `ocr.provider="tesseract_js"`, and `ocr.readiness="reachable"`; it must also show reachable storage/scanner/database/limiter/model prerequisites before OCR is represented as available.
6. Perform staging owner-isolation acceptance: clean PNG and JPEG extraction, WebP extraction, blank image/no-readable-text result, infected-file rejection, scanner timeout/outage, cross-user source/page denial, deleted-object handling, cancellation/time-limit behavior, restart/lease recovery, reindex duplicate suppression and source deletion while queued.
7. Test text-PDF native extraction separately. Test scanned PDF rejection until a separate renderer is deployed and accepted; do not represent it as supported.

Rollback by first disabling `KNOWLEDGE_OCR_ENABLED` on API and worker, wait for or safely fail in-flight jobs, then deploy the retained prior release. Do not make the private bucket public or weaken scanner checks to recover service.

## Local controlled evidence

`tests/local-ocr-v127.test.ts` recognizes static known-text PNG/JPEG fixtures with the package-managed engine, verifies readiness smoke recognition, catches the canonical `type: "image"` eligibility regression, proves scanner-state rejection at both route and worker boundaries, and records a blank image as no-readable-text. These are implementation/local controlled tests only.
