## Deployment and rollback requirements

Before an authorized rollout: review `V1.3.0_IMPLEMENTATION_AUDIT.md`, preserve a PostgreSQL backup/restore point, supply/rotate a real `API_KEY_HASH_SECRET`, verify shared Redis, apply migration 009 through the normal runner in an approved environment, and execute controlled session/create/use/revoke/expiry/capacity/model checks. Inspect logs only after confirming secret redaction. Do not use a client/browser key or internal model key in examples.

Rollback is code/configuration-first and data-preserving: disable external API traffic, revoke exposed keys as appropriate, allow active work to finish/fail safely, retain additive tables/audit rows and backups, and deploy the matched preceding release after session/model checks. Do **not** drop migration 009 merely to roll back code. See `ROLLBACK.md` and `V1.3.0_DEFECT_BLOCKER_REGISTER.md`.
