# v1.2.5 Security Findings and Mitigations

## Remediated findings

| Severity | Finding | Mitigation | Evidence |
| --- | --- | --- | --- |
| High | Editing/resubmitting a user message changed public-share scope/content without incrementing the share revision. | Resubmit now increments `share_version` in the same transaction as message edit, trailing soft deletion and retitle. | `tests/share-revision-v125.test.ts` stale-preview/resubmit regression. |
| High | Revision-only proof did not independently bind publication to the reviewed candidate content. | Locked preview and create flows calculate/recheck a server-side ordered SHA-256 candidate digest; creation verifies its copied snapshot digest. | `tests/share-revision-v125.test.ts` forged proof, race, retry and simultaneous-publication coverage. |
| Medium | No repository/REST mutation boundary existed for message soft delete/restore with share invalidation. | Added owner-scoped transactional soft-delete/restore methods and REST routes, both versioned. | `tests/share-revision-v125.test.ts`. |
| Medium | Artifact deletion could return success after a private-object delete outage. | Storage deletion must succeed before success. Failed deletion restores metadata availability where possible and returns a retryable 503. | `tests/artifact-lifecycle-v125.test.ts`. |

## Existing controls reviewed and retained

- First-party Argon2id authentication, opaque hash-backed sessions/reset tokens, CSRF checks, CORS origin allowlist and authentication/abuse limits.
- Owner-scoped PostgreSQL resource queries for conversations, messages, artifacts, memories, knowledge records and shares.
- High-entropy, SHA-256-hashed public bearer tokens; no raw token database storage or logging path.
- Finite 1h/24h/7d/30d server-derived share expiry; generic public unavailable responses for invalid/expired/revoked tokens; non-cache/no-referrer/no-index public headers and public/create burst limits.
- Private S3-compatible storage paths, server-generated opaque keys, MIME/filename bounds, scanner gating for upload paths, ZIP constraints and owner-authorized artifact download.
- Conventional retrieval rejects prohibited schemes, credentials, non-standard ports, private/loopback/link-local/multicast/reserved IPv4/IPv6 ranges, IPv4-mapped IPv6, unsafe redirects and mixed DNS answers; connections use a checked/pinned resolver result.
- No arbitrary model-generated code execution, browser worker, OCR, vector retrieval or synthetic streaming is enabled.

## Remaining security acceptance blockers

These are not code-success claims:

1. **Live PostgreSQL transaction/lock semantics:** `pg-mem` does not provide full PostgreSQL transactional rollback fidelity for forced late-statement failures. Local tests verify transaction `BEGIN`/`ROLLBACK` control flow; an actual PostgreSQL staging rollback and concurrency test remains required.
2. **Private storage and ClamAV:** controlled adapter and local protocol tests pass, but real IAM/ACL, storage failure, deletion, scanner timeout and malware-signature staging acceptance require credentials.
3. **Rendered browser extraction:** unavailable until a separately isolated, egress-controlled browser worker can be provided and adversarially tested.
4. **OCR/vector/sandbox:** unavailable until approved isolated services and real acceptance environments exist. No insecure in-process substitute was added.
5. **Streaming:** unavailable until the owner verifies the protected inference endpoint's documented streaming contract.
6. **Deployment edge behavior:** CDN/proxy headers, cookie behavior, CORS, Redis multi-instance limits, S3 endpoint policy and Render/Netlify readiness need a controlled deployed test.

## Security recommendation

No new high-severity local code defect remains from the confirmed v1.2.4 sharing/artifact issues. The release remains a **release candidate**, not production-ready, until real service and deployment acceptance resolves the listed blockers.
