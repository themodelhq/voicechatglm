## 2. Confirmed defects repaired

### Conversation-sharing revision integrity — repaired

The confirmed v1.2.4 defect was in `resubmitConversationUserMessage()`: it updated a user message, soft-deleted later messages and retitled the conversation without incrementing `share_version`. v1.2.5 increments `share_version` inside the same transaction.

v1.2.5 also implements defense in depth:

- locked coherent preview reads;
- server-calculated ordered SHA-256 candidate proof across all eligible scoped messages;
- mandatory revision plus proof at create time;
- locked recomputation before publication;
- immutable snapshot proof verification before commit;
- additive `006_share_preview_integrity.sql` persistence of the non-bearer proof;
- owner-scoped transactional soft-delete and restore message paths;
- explicit post-persistence Copy link UI rather than a false automatic-copy claim.

### Artifact deletion success semantics — repaired

The former route could report successful deletion when storage deletion failed. v1.2.5 returns success only after storage removal. A storage-delete failure restores metadata to available/private state where possible and returns `503 ARTIFACT_DELETE_FAILED`.
