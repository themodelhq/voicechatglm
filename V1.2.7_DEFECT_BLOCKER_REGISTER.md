# v1.2.7 defect and blocker register

**Assessment date:** 2026-10-10  
**Scope:** source tree and controlled local execution only

## Resolved in this release

| ID | Severity | Finding | Resolution | Evidence/status |
|---|---|---|---|---|
| OCR-001 | High | Previous OCR was an external-contract adapter; no real local engine was present. | Added pinned production `tesseract.js@5.1.1` and `@tesseract.js-data/eng@1.0.0`, local adapter, smoke fixture and real PNG/JPEG tests. | **PASS — implementation/local controlled test** |
| OCR-002 | High | Uploaded images are canonically stored as `detected_type = image`, while knowledge eligibility checked `png/jpeg/webp`; OCR could be skipped. | Eligibility now accepts canonical image type and approved image MIME values in route and worker logic. | **PASS — regression test** |
| OCR-003 | Critical | A knowledge/OCR request could be attached before scanner-success status, and a queued job did not recheck status. | Route and worker both require scanner-success states; ambiguous, missing, timeout/outage and non-clean states fail closed. | **PASS — regression test** |
| OCR-004 | High | Local image-only OCR could be mistaken for scanned-PDF support. | Local provider returns an explicit `OCR_PDF_RENDERER_UNAVAILABLE`; documentation and capability wording do not claim PDF raster support. | **PASS — source/config review and controlled test** |
| OCR-005 | Medium | Empty OCR could create a chunk containing only a synthetic page label. | Empty output is persisted as an owner-scoped partial page/source with `completed_no_text` metadata and zero chunks. | **PASS — regression test** |
| OCR-006 | Medium | OCR capability/readiness could show configured despite a missing engine/language data. | `/api/readiness` runs a real local fixture recognition; capability availability requires that result plus file/database readiness. | **PASS — implementation/local controlled test** |
| JOB-001 | Medium | A source could receive duplicate active indexing work; expired worker leases were not reclaimed. | Source/file locking and active-job reuse suppress duplicates; expired leases requeue or become terminal at the retry bound; worker status reflects scheduled retry. | **PASS — source-level controlled coverage; no live multi-worker acceptance** |
| PKG-001 | High | A standalone 23 MB `eng.traineddata` model-data file was present in the release tree. | Removed it. OCR language data is package-managed at deployment; the final archive excludes standalone weights and `node_modules`. | **PASS — release-tree inspection pending final archive verification** |

## Scope safeguards retained

- No subscription, credit, paywall, artificial daily/monthly quota, voice/speech feature, image generation feature, Auth0 integration, model replacement, model upload, retraining, self-hosting or model-asset change was made.
- No supplied or model-generated code is executed by the main API. The separate sandbox/browser capability remains unavailable unless its independently verified service is configured.
- No secret, database dump, user document, user OCR result, cache, `node_modules`, or standalone language/model file belongs in the release archive.
