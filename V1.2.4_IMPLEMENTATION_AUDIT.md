## Actual v1.2.3 findings

1. Conversation shares allowed an omitted expiry, so a link could be indefinitely valid.
2. Full-share preview and retrieval selected only the first 1,000 eligible messages. This silently made a purported full share incomplete.
3. A full share dynamically read the live conversation instead of a consistent published state.
4. Public share pagination did not exist; public error/cache hardening and public-route burst protection were incomplete.
5. Calls to `consumeUserAction` in upload, analysis and routed-tool call sites passed arguments in the wrong positions, weakening their intended per-user burst enforcement.
6. OCR, semantic/vector retrieval, isolated arbitrary-code execution, JavaScript browser rendering and upstream token streaming still have no required deployed infrastructure or direct upstream evidence.

## Implemented v1.2.4 repair set

### Finite, immutable public sharing

- Added migration `005_share_expiration_snapshots.sql`.
- New shares only accept exactly **1 hour, 24 hours, 7 days or 30 days**. Creation requires a server-validated expiry and a preview version; there is no permanent-link control or optional expiry fallback.
- Legacy records whose `expires_at` was null are set to their historical `created_at` at migration time. They are therefore expired at the documented migration cutoff, never silently extended. This is deliberately conservative.
- Added `conversations.share_version`, incremented within conversation mutation transactions. Creation rejects a stale preview with HTTP 409 rather than publishing a changed state.
- Added private `conversation_share_messages` snapshot rows. Full and selected shares copy only eligible user/assistant content, original role and timestamp in deterministic `created_at,id` order. Copying is keyset-paged in groups of 100, not an unbounded application-memory load.
- Public retrieval is snapshot-paginated (100 maximum per page), checks expiry/revocation under a share-row lock, and never reads dynamic conversation history. No 1,000-message truncation remains.
- Public responses do not carry attachments, artifact IDs/keys, message metadata, memory, knowledge, system prompts or tool data. No public attachment route was added.

### Share security and user experience

- Retained 256-bit cryptographically random bearer tokens and SHA-256 database hashes; no raw token is persisted by repository methods or logged by these routes.
- Added explicit preview/review dialog with scope, title, permitted content, count, selected expiry, attachment statement, privacy statement, cancel and final confirmation.
- Added owner share-management details (scope, count, creation, finite expiry and revoke control), expired/revoked/invalid public unavailable state, temporary-unavailable handling and paginated public display.
- Added public retrieval and authenticated create/preview/revoke burst protection using the existing Redis/local limiter abstraction. Corrected the pre-existing argument-position bug at upload, analysis and routed-tool limiter call sites.
- Public share responses use `Cache-Control: no-store`, `Referrer-Policy: no-referrer` and `X-Robots-Tag: noindex, noarchive, nosnippet`; the public response remains token-only and uses the generic unavailable response.
- Expired metadata is removed by maintenance; expiry is always checked at retrieval, so cleanup is not an authorization control.

### Deliberately unchanged advanced boundaries

The release retains lexical owner-scoped knowledge retrieval and deterministic CSV/XLSX operations. It does not claim OCR, embeddings/vector/hybrid retrieval, browser automation, isolated arbitrary code execution, synthetic streaming, upstream streaming, public storage or a live deployment. The protected model ID/revision is preserved unchanged.

## Smallest-safe-change rationale

The repair adds a private snapshot table and an additive migration rather than redesigning conversations, artifacts, object storage, authentication, model transport or deployment topology. Existing private ownership and artifact boundaries remain in force. No dependency was added or upgraded; the root lock graph was preserved except for the release version metadata.
