# v1.2.8 secure document processing — historical activation record

> **Superseded for current operation:** v1.2.9 repairs same-page native-plus-raster PDF extraction and introduces strict OCR profiles. Use [V1.2.9_OCR_DOCUMENT_PROCESSING.md](V1.2.9_OCR_DOCUMENT_PROCESSING.md) for current configuration, behavior, and acceptance steps. This file is retained only as the v1.2.8 release record.

## Scope and exact implementation

v1.2.8 adds one server-only, scanner-gated document-processing path for both ordinary chat attachments and Knowledge indexing. It preserves the existing Netlify React frontend, Render Node API, PostgreSQL authorization/jobs, Redis-compatible limits, private object storage, ClamAV/equivalent scanner, first-party authentication, and protected model contract.

- **OCR engine:** exact locked `tesseract.js@5.1.1` with `@tesseract.js-data/eng@1.0.0`; English (`eng`) only.
- **PDF renderer:** exact locked `pdfjs-dist@5.4.149` with `@napi-rs/canvas@0.1.100`. This is an in-process, package-managed renderer compatible with the Node 20 deployment profile. No Poppler, Ghostscript, system Tesseract, shell, user-controlled executable/path, browser request, or user-URL fetch is used.
- **PDF behavior:** every page is inspected for native text. A page containing the configured meaningful-text threshold (default 12 characters) is kept as `native_text`; only pages below that threshold are rasterized and OCR'd. Page order and per-page method/status/confidence (where supplied by OCR) are persisted as bounded provenance.
- **Supported upload inputs:** signature-validated PNG, JPEG, WebP, and PDF. OCR recognition is English-only. PDF support is real local fixture evidence, not a general visual-understanding claim.
- **Not supported:** image interpretation beyond text extraction; handwriting/quality guarantees; password-protected/encrypted/malformed PDFs; PDF pages or raster output beyond configured limits; non-English language data; remote URL/document fetching; and arbitrary Office-image OCR.

## Private flow and authorization

1. The API validates the extension/signature and writes the original to private quarantine storage.
2. The scanner must report clean. Scanner unavailability is a fail-closed error; an unscanned object never reaches native extraction, rendering, OCR, Knowledge processing, or model context.
3. The API promotes the clean object, writes a private extraction artifact, and stores owner-scoped PostgreSQL metadata. Non-OCR document extraction is redacted before artifact persistence.
4. On chat analysis, `loadRecords` selects only files owned by the authenticated user and independently rechecks scanner-success status. For clean image/PDF attachments it reads private object bytes, runs the shared processor, redacts page text before artifact/model use, and stores only the protected extraction artifact.
5. On Knowledge indexing, the leased worker retrieves the owner-scoped source/file, independently repeats the scanner-success check, then reads private bytes and invokes that same processor. It derives bounded Knowledge pages/chunks from the protected page text.
6. Chat model evidence uses the existing labelled, bounded, prompt-injection-delimited source path. Knowledge chunks retain owner namespace and existing retrieval authorization. Deletion remains owner-scoped and removes original/extraction/result keys through the existing lifecycle.

The server never trusts a client owner ID, exposes a storage key, emits a public object URL, or forwards scanner/storage/model credentials to the browser.

## Limits and failure semantics

Defaults are configured in `.env.v128.example` and the Render blueprint. Invalid limit values mark OCR/PDF configuration unavailable rather than silently loosening a bound.

| Control | Default | Enforced behavior |
| --- | ---: | --- |
| OCR worker slots per process | 1 (allowed 1–4) | abort-aware process-wide queue around Tesseract worker lifecycle |
| Source image bytes | 8 MiB | rejects oversize OCR input |
| Source image pixels | 20,000,000 | signature + dimension check before worker creation |
| OCR image output | 250,000 chars | bounds a page recognition result |
| PDF pages | 20 (allowed 1–40) | rejects before page processing when exceeded |
| PDF page processing timeout | 90 s | cancels PDF load/render work and returns truthful timeout |
| PDF render scale | 1.5 | reduced only to satisfy the page-pixel bound |
| Rendered page pixels | 10,000,000 | rejects unsafe rasterization |
| Total rendered PDF pixels | 40,000,000 | rejects cumulative raster work |
| PDF page dimensions | 14,400 points/axis | rejects pathological page geometry |
| PDF output | 500,000 chars | stops retaining further OCR text; reports partial/truncated output |
| Chat extraction | existing 120,000 chars/file policy | bounds private artifact/context contribution |

`OCR_PDF_INVALID`, `OCR_PDF_ENCRYPTED`, page/dimension/pixel limits, renderer unavailability, OCR unavailability, timeout, and cancellation are explicit protected-path outcomes. Native PDF text may be used with a partial notice only when the local OCR engine is unavailable; a scanned-only image/PDF analysis fails truthfully instead of pretending analysis occurred.

## Confidential-content handling

OCR/native PDF page text is treated as untrusted uploaded text. v1.2.8 applies the existing standalone secret redaction policy **per page before** page hashes, extraction artifacts, Knowledge chunks, and model evidence are built. Values that can be redacted are replaced with `[REDACTED]`; private-key material that cannot safely be redacted is excluded from that page. A notice records redaction/exclusion without retaining the removed text. Source content remains prompt-injection-delimited and never becomes trusted instructions.

## Required Render configuration

Use `render.yaml` as a reviewed activation profile and apply the same OCR variables to both `voicechatglm-api` and `voicechatglm-knowledge-worker`. Keep `KNOWLEDGE_OCR_ENABLED=false` until the following acceptance runs pass. `KNOWLEDGE_OCR_MAX_CONCURRENT_JOBS=1` is the conservative production default; increasing it must be capacity-tested and remain at most 4.

The locked package dependencies must be installed by `npm ci --omit=dev` on Node 20.20.2. Do not add undeclared native PDF/OCR binaries as a deployment workaround.
