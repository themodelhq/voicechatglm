## 4. Conversation-sharing regression evidence

**PASS — independently executed** in `tests/share-v124.test.ts`, `tests/share-http-v124.test.ts`, `tests/share-dialog-v124.test.tsx`, existing durable tests and configuration tests:

- Explicit finite-only expiry validation: rejects omitted, zero, negative, unsupported and excessive values; permits 1h/24h/7d/30d.
- Server-clock expiry calculation, expiry enforcement before cleanup and immediate owner revocation denial.
- Hashed high-entropy token behavior; raw token is returned only at successful creation and is not a database field returned by repository share metadata.
- Fresh migration and v1.2.3 upgrade behavior.
- Zero eligible messages, selected scope, full scope and cross-owner denial paths.
- Full-share completeness at 999, 1,000, 1,001 and 2,001 eligible messages. Public pages reconstruct every message exactly once, in stable order, with no silent 1,000-message ceiling.
- Exclusion of system/tool content and message metadata/attachments from published data.
- Snapshot/preview version conflict after a concurrent mutation returns a recoverable 409 rather than publishing a changed conversation.
- Public pagination, `Cache-Control: no-store`, `Referrer-Policy: no-referrer`, `X-Robots-Tag: noindex, noarchive, nosnippet`, generic rate-limit response and public burst limit.
- Review dialog scope/content/expiry/confirmation behavior.

**NOT TESTED:** actual browser clipboard behavior, actual multi-instance Redis behavior, real PostgreSQL locking behavior under load, CDN/proxy cache behavior or a deployed public-share URL. No raw share token is retained in this report.

## 8. Unresolved defects / blockers

No final local validation failure remains. The following are intentionally incomplete, not hidden as success:

1. OCR requires an approved isolated OCR service/runtime and real acceptance cases.
2. Semantic/vector/hybrid retrieval requires a documented embedding model/version and verified vector infrastructure.
3. General code execution requires an external hardened sandbox; it is not executed in the Node API.
4. Streaming requires a documented protected-upstream stream contract and end-to-end cancellation tests.
5. Browser rendering requires an isolated maintained browser worker with egress/resource controls.
6. Live acceptance requires user-provided Render/Netlify, PostgreSQL, Redis, private storage, ClamAV, protected-model and Brave/staging access.
